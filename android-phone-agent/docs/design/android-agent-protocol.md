# 安卓 Agent：蓝牙协议与模块接口

版本：0.2，2026-10-20。状态：首版实施契约，尚无实现与实机通过声明。上位设计见 [开发方案](android-agent-development-plan.md)。本文件定义新增安卓固件协议，不是原 iPhone 固件已支持的功能。

## 1. 连接角色和执行边界

- Android App：BLE Central、任务与输入的唯一调度者。
- ESP32-S3：GATT Peripheral、USB HID 鼠标/键盘、可中断动作执行器。
- BLE 只传指令、回执、设备状态；不传屏幕图片、视频、模型 Key 或聊天记录。
- 文本若经 HID 输入，其 ASCII 内容会经过 BLE，因此指令也必须保护隐私。中文 IME 文本在手机内部提交，不转发板子。
- 一个运行会话只允许一个授权控制者和一个动作。首版不提供多控制者和多手机切换；异常不会退回无障碍、ADB 或未认证串口输入。
- USB 已枚举不等于手机操作生效；BLE 已连接不等于已认证；GATT 写入成功不等于动作完成。

## 2. GATT 服务

为安卓版本分配独立服务，禁止直接复用旧 iOS 服务后静默改变语义。以下 UUID 是本方案的新分配值，实施时在 App/固件/协议测试中保持一致。

Service：`50e00000-7cc6-47b9-8e6f-6f59d90e0000`。

| 特征后缀 | 名称 | 属性 | 用途 |
|---|---|---|---|
| `0001` | INFO | read | 不含秘密的协议版本、板子标识和固件标识；认证前仅供发现参考 |
| `0002` | COMMAND | write-with-response | 握手消息、认证后的 action/query 等普通请求 |
| `0003` | EVENT | notify | 握手回应、动作回执、能力与状态 |
| `0004` | CONTROL | write-with-response + notify | 独立缓冲的 heartbeat/stop 及其回执，不进入普通动作队列 |

完整 UUID 只替换 service 最后四位。所有控制特征要求加密链路；完成应用层双向认证前不接收任何 HID 动作。不提供旧版裸 `cmd`、debug relay 或另一 BLE HID 服务作为旁路。

App 先发现服务和订阅通知，再执行握手。协议不匹配时保持不可控制，展示升级提示；广播名、INFO 及 MAC 均不能单独证明身份。

## 3. BLE 传输和资源上限

首版必须在 ATT MTU=23 下工作；更大 MTU 只作为优化。每条 characteristic value 上限为协商 MTU−3，且不得超过所用 BLE 实现的特征值上限。不可依赖 Android 一定接受某个请求 MTU。

每个分片使用固定 8 字节头，整数为小端：

| 字段 | 长度 | 约束 |
|---|---|---|
| `wire_version` | u8 | 2 |
| `flags` | u8 | 握手明文/认证密文类型；其余位必须为 0 |
| `transfer_id` | u16 | 连接内分片组编号，不承担防重放功能 |
| `fragment_index` | u8 | 从 0 开始，必须按序 |
| `fragment_count` | u8 | 1..255，与长度/片大小一致 |
| `total_bytes` | u16 | 完整封包长度，不是本片长度 |

MTU=23 时每片可带 12 字节消息内容。先编码完整逻辑消息，再切分；不能对每片独立解析 JSON 或执行动作。普通消息上限 1024 字节，握手上限 512，控制消息上限 128；上限均包含完整加密信封。不得按对端声明长度无限分配内存。

每连接最多一个普通组装槽和一个控制组装槽。普通组装拟定超时 2 秒，控制组装拟定超时 1 秒；MTU=23 压力测试后定稿。异常、断连或会话失效清除半包。组装未结束不能被另一 transfer 静默覆盖；明确取消旧 transfer 后才能开始新的普通传输。

App 维护单一 GATT 操作队列，仅一个写请求在途；每片都等待系统回调并处理超时。到下一个分片边界时优先处理停止和到期心跳，普通长包不垄断链路。控制特征使用独立缓冲，但不声称可以绕过 Android 蓝牙栈中已经在途的操作。

## 4. 设备绑定与会话保护

每台板子有独立 32 字节随机绑定 secret，禁止整个产品共用一个写在 APK 中的 secret。生产设备凭证以二维码交付，开发阶段经原生 USB 写入/读取。二维码包含协议标识、板子 ID 与绑定 secret；模型 Key 与它完全分离。绑定重置需本地物理操作或受控开发期 USB，不允许未授权远程重置。

使用平台密码库实现 HMAC-SHA256、HKDF-SHA256、AES-256-GCM、密码学随机数与常数时间比较，不手写密码算法。BLE bonding/加密与应用层身份验证同时存在；Just Works 不作为设备身份认证依据。

握手流程：

1. App 发 `client_hello`：版本、预期板子 ID、32 字节 App 随机数。
2. 板子回自己的 32 字节随机数、受支持功能位和 board proof。
3. 双方以固定二进制 transcript 计算 HMAC：域标识、版本、板子 ID、双方随机数、功能位；board/app proof 使用不同角色标签，App proof 还绑定 board proof。
4. 双方验证后，用 HKDF 从绑定 secret 与 transcript 派生会话标识、方向和通道各异的 AES-GCM 密钥及 nonce 前缀。板子返回经新会话保护的 `auth_ok`；App 验证后才进入 READY。

transcript 不能依赖 JSON 字段顺序；原始字段长度、编码和测试向量在编码器测试中固定。未认证状态仅允许上述有限握手，设超时、失败次数与速率限制。能力列表未经握手证明不得用于授权动作。

认证后每个封包包含 `version / message_type / session_id / sequence / command_id / payload_length`，这些字段作为 AES-GCM AAD；负载为严格 UTF-8 JSON 密文，使用完整 16 字节 tag。nonce 为每方向/通道独立的 8 字节会话前缀加 u32 序号；同一密钥不允许复用 nonce。四个方向/通道分别派生密钥并维护递增序号，避免控制消息抢占普通分片后造成序号相互阻塞。

序号从 1 开始，拒绝旧序号或重复序号；耗尽前重建会话，不回绕。`session_id`、`command_id` 与安全序号不能混为一个字段。片组编号只用于组装；完整封包验签解密、版本与长度检查通过后才允许影响状态或续租。HMAC 只用于握手，不把 HMAC 当作加密。

实施先写 Android/ESP32 共享测试向量和篡改/重放用例，再开放 HID 执行；原语调用及 nonce 使用须纳入代码复核。

## 5. 会话、命令和结果语义

建议状态：`DISCONNECTED → DISCOVERING → LINKED → AUTHENTICATING → READY`，异常进入 `RELEASING / FAULT`。USB 不可用或校准无效时可保持连接，但不能伪装为动作已就绪。

认证后请求至少携带操作名、命令 ID、输入参数；信封携带会话和安全序号。首版消息类型如下：

| 操作 | 请求或响应语义 |
|---|---|
| `capabilities/status` | 获取固件版本、USB 状态、能力、忙闲、最后命令及释放状态 |
| `heartbeat` | 只有当前控制者的有效认证消息可续租 |
| `action` | 有界动作；只允许当前会话提交 |
| `accepted` | 参数有效且已接管该命令，不表示手机已变化 |
| `started` | 开始输出动作；为诊断保留 |
| `done` | HID 报告序列结束并释放本动作按住状态，不表示任务成功 |
| `rejected/cancelled/error` | 明确失败原因、对应命令及释放状态 |
| `stop/stopped` | 撤销执行权、取消动作与队列，释放后回执 |
| `query_result` | 查询命令状态，不重新执行 |

命令 ID 在会话内单调增加；同 ID/同负载返回已有状态，不执行第二次，同 ID/不同负载拒绝。结果缓存拟定 64 条，淘汰后仍保留已接受 ID 水位；不能把已淘汰旧 ID 当成新动作。

普通动作只允许一个在执行，新的普通动作在 BUSY 时拒绝，首版不预排多个 UI 动作。完整普通命令验收前没有 `accepted`；收到通知但 App 没处理到仍不能推导用户可见状态。

心跳拟定每 500 ms，租约 1.5 秒；参数是待实测的工程目标。控制者断开立即撤销其会话，不等其他连接断开。协议首版不允许第二控制者抢占；没有控制权的连接不能续租、停止或查询敏感结果。

## 6. 动作表与坐标

模型输出与板子协议分开：模型只输出完整截图上的整数 0..1000 坐标；App 验证后按校准转换到 HID 计数。固件不得把 HID 计数再当 0..1000 映射一次。传输字段使用 `x_counts/y_counts` 等明确名称，计数范围拟定 0..4096，超界拒绝、不静默截断。

| 动作 | 首版参数与边界 |
|---|---|
| `tap` | 一个已校准落点，按下/释放由固件内部完成 |
| `swipe` | 起终点、拟定 50..3000 ms；先定位再拖动，异常必释放 |
| `long_press` | 落点、拟定 400..3000 ms |
| `scroll` | 拟定 −10..10 且非零的整数滚动量 |
| `type_ascii` | 单命令最多 128 个可打印 ASCII；拒绝控制字符及 Unicode |
| `key` | 首版仅 Enter、Backspace、Esc、Tab、方向键等明确枚举 |
| `locate/calibrate` | 仅 App 校准流程可用；不暴露任意裸按下/无限长移动给模型 |
| `wait` | 由 App 执行可取消等待，不作为持续占用板子的长任务 |

全部固件动作有总时限，拟定上限 8 秒，包括归位、定位和手势。原固件循环必须拆成短步骤，让停止、心跳及 USB 异常能随时处理。复杂 path/circle、系统 Home/Back/Recents 在单独验证后通过能力协商启用，不假设 iOS 按键映射在安卓有效。

校准由 App 内测试 Activity 接收真实鼠标点击事件，拟合计数到像素关系，并用独立检查点验收。不依赖 MediaProjection 一定采集到鼠标指针。校准绑定手机本地安装 ID、屏幕尺寸/方向、设备与固件协议；指针速度变化或明显偏差要求重新校准。

## 7. 停止、未知结果和重连

App 的停止顺序：递增任务 generation、撤销输入令牌、取消模型/待发普通动作 → 优先发送 stop → 等待或报告设备释放结果。模型回包与执行前都检查 generation，晚到响应直接丢弃。

固件停止顺序：禁止旧动作继续提交 HID → 取消余下步骤并清空半包/待执行动作 → 释放鼠标、键盘和 consumer → 回 `stopped`。若 USB 拔出，只能报告本地清理和 `release_sent=false`；重连先补中性报告再允许动作。释放失败则维持 FAULT，不能显示“已确认释放”。

健康连接停止输出目标为 300 ms；失联释放目标为最后心跳后 1.5 秒。均为验收目标而非当前实现保证。若 GATT 在途请求堵塞，App 撤销后续发送并断开，依靠设备租约兜底，同时展示结果未知。

命令可能已执行而 `done` 丢失：同会话先查询结果，结合新截图判断；跨会话/设备重启不具备持久化的恰好一次保证。App 必须显示 `ACTION_UNKNOWN` 或 `SEND_UNKNOWN`，禁止自动重发点击、输入和发送。

必须覆盖的竞态：停止与下一条 HID 报告并发；旧连接断开回调晚于新会话认证；HID 已完成但结果回执丢失。用连接代际、任务代际、去重水位及模拟时序验证，不只测顺序正常路径。

## 8. App 内模块契约

| 接口 | 最少职责与数据 |
|---|---|
| `ScreenSource` | `start/observe/stop`；返回 projectionEpoch、frameId、receivedAt、已核实的采集时间（可空）、尺寸/方向、图像与观察状态 |
| `ModelClient` | 输入目标/上下文/截图与能力，返回严格决策或分类错误；可取消；拒绝非法结束、超长、重复 JSON key 和越界参数 |
| `DeviceSession` | 独占 BLE 连接与控制租约；连接 generation、USB/校准状态、能力、请求/回执关联 |
| `ActionExecutor` | 仅接受经过验证、绑定观察与任务 generation 的动作；执行前重新检查，串行化，支持 cancel/stop |
| `AgentRunner` | 单任务、步数/时间/调用预算、观察/规划/执行/核验和暂停恢复，不直接操作 GATT |
| `TextInputBridge` | 仅在用户选中本 IME 时工作；内部 IPC，当前编辑 epoch、目标包名、InputConnection 与文本提交/读回状态 |
| `TraceStore` | 默认只保存状态、动作类型、耗时和分类错误；不存 Key、配对凭证、截图或完整聊天 |

模型决策最少为 `action/arguments/reason/expected`，不允许模型指定会话、认证参数、观察 ID 或设备身份。实际编码严格拒绝未知动作和无关参数。

IME 不开放任意外部广播注入。仅同 UID/签名受保护的内部通道接收一次性文本操作；绑定编辑会话、操作 ID、用户确认及可验证草稿。编辑会话变化即作废。`EditorInfo.packageName` 只能约束目标应用，不能确认微信联系人；联系人仍由用户确认及视觉上下文限制。

## 9. 必需测试向量

- MTU 23、较大 MTU、变化/失败的 MTU 协商、分片超时/重复/乱序/超长、并行普通与控制包。
- 正确/错误设备凭证、篡改握手、不同角色 proof、错误 tag、跨会话/跨方向/跨通道重放、序号耗尽。
- 第二连接无权限，旧回调不能清掉新会话，控制者离开但其他连接仍在时立即释放。
- STOP 插入每个动作阶段与分片阶段；模型/设备回执晚到不得复活任务。
- 同 ID 同内容不重复输入，同 ID 不同内容拒绝，缓存淘汰后旧 ID 不重新执行。
- 断线前后 USB 按键状态、设备复位、USB 挂起/拔出与中性释放；没有真机时明确仅为模拟结论。
