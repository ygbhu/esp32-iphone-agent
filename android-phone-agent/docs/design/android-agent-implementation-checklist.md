# 安卓 Agent：开发任务与验收矩阵

版本：0.2，2026-10-20。上位方案：[开发方案](android-agent-development-plan.md)；接口依据：[协议与模块接口](android-agent-protocol.md)。任务未勾选表示尚未实现，不代表阻碍设计交付。

## 1. 已冻结的首版范围

| 项目 | 决策 |
|---|---|
| 运行主体 | 同一台安卓手机上的原生 APK |
| 屏幕来源 | 用户授权的 MediaProjection，非无障碍树 |
| 点击、滑动、按键 | BLE → ESP32-S3 → USB HID |
| 中文 | 同 APK 可选 IME；用户已同意，需手动启用选择 |
| 模型 | App 使用用户填写的 Key 直连现有 AI 网关 |
| 服务端 | 不开发账号、收款、订阅或模型中转服务端 |
| 手机范围 | 不设品牌/型号白名单；按系统版本和能力自检 |
| 初始系统基线 | Android 11+；target SDK 按实施时要求，版本行为分别适配 |
| 禁用路线 | 无障碍、ADB 执行/截图、Root、电脑常驻 Agent |
| 蓝牙与网络 | BLE 传指令和状态；手机正常上网；板子不启动 Wi-Fi/AirPlay/视频 |
| 当前测试条件 | 已有 S3，但暂无安卓真机；先软件构建/模拟，再补硬件验收 |

## 2. 建议源码目录

```text
android-phone-agent/
  android/
    app/                         # Activity、Compose、前台服务、InputMethodService
    core/                        # 状态机、动作/模型 schema、预算与停止语义
    device/                      # BLE、认证、分片、设备会话与能力
    capture/                     # 投影授权、截图、坐标与观察有效性
    model/                       # OpenAI 兼容客户端、配置、错误分类
    input/                       # 校准、动作执行、内部 IME 桥接
    test-fixtures/               # 仅调试的画布、编辑框和模拟聊天，不进入用户主流程
  firmware/
    src/                         # 安卓固件目标，USB HID + BLE，不链接 AirPlay
    tests/                       # 协议和动作状态机的主机模拟
    board-profiles/              # 实际板型、Flash、USB 与构建配置
  protocol/
    schema/                      # 动作、状态、错误码与版本
    vectors/                     # 跨端编码、握手、加密、分片和去重样例
  docs/                          # 安装、恢复、兼容状态与实机报告
```

上面的目录是边界建议，不要求首日拆成大量 Gradle 发布模块。可先在单 APK 内按 package 分层，先验证依赖关系再按需要拆模块。保留上游版权和改动来源，不修改原始参考检出与备份。

## 3. 实施工作包

### M0：规格与开发环境

- [ ] T00-01 新建独立开发目录，记录上游 commit 和实际移植文件；确认许可证和原固件备份路径。验收：参考检出无改动，恢复资料可定位。
- [ ] T00-02 安装并锁定 Android SDK、JDK、Gradle Wrapper、AGP/Kotlin 与固件工具链。验收：Windows 可构建空 APK 和安卓固件目标；记录实际版本，不依赖“电脑上可能已安装”。
- [ ] T00-03 固定协议编码、UUID、错误枚举、消息上限和安全封装，制作双方一致测试向量。验收：Kotlin 与 ESP32/主机模拟结果逐字节一致，错误 tag/重放不能通过。
- [ ] T00-04 建立假截图、假模型、假 BLE/USB sink 与调试测试页面。验收：离线跑通一次观察→动作→核验，不连接真实账户、不调用付费模型。
- [ ] T00-05 确认实际 S3 配置，保留现有 16 MB Flash 全量备份。验收：构建布局和硬件容量分别记录，不为“用满 Flash”擅自改分区或清除备份。

### M1：安卓 App 基础与截图/模型

- [ ] T01-01 首页、设备、模型设置、任务/记录、校准和输入法引导。验收：各状态显示真实依赖，不用 DEMO 成功状态掩盖未连接。
- [ ] T01-02 用户 Key 加密存储、掩码、修改/清除；发布配置预置 endpoint/model，开发版提供高级设置。验收：导出日志、备份与异常文本均无 Key。
- [ ] T01-03 系统录屏授权和前台服务完整生命周期。验收：拒绝/撤销授权、重复启动、旋转、进程终止均不继续使用旧投影令牌。
- [ ] T01-04 有界截图、压缩、尺寸映射和帧元数据。拟定长边不超过 1280、JPEG 质量约 75 作为起点；文字辨识和耗时实测后调整。验收：不积压、不泄漏 Image 对象，不把接收时间冒充已证实的采集时间。
- [ ] T01-05 OpenAI 兼容视觉请求与严格响应解析。验收：合成图和假服务器覆盖成功、401/403/429、余额类错误、超时、拒答、截断和非法 JSON；真实网关配置提供后再单独接入。
- [ ] T01-06 自身设置页与敏感内容防上传。验收：任务在自身 Key/设备设置界面暂停，模型 content、截图与日志不包含凭证。

### M2：BLE 与硬件手控

- [ ] T02-01 固件抽出 HID、BLE、配置和可中断动作调度，构建不启动 AirPlay/Wi-Fi/视频。验收：编译依赖及开机状态一致，不残留可执行的旧控制旁路。
- [ ] T02-02 App 扫描、权限、绑定、通知订阅、双向认证及断开。验收：未授权连接、错误 secret、第二控制者均不能输入；不凭设备名自动信任。
- [ ] T02-03 分片、GATT 操作队列、心跳、结果查询和命令去重。验收：默认 MTU 23 可工作；控制包可在普通分片间优先发送，组装超时有界。
- [ ] T02-04 可中断 tap/swipe/long_press/scroll/type_ascii/key，所有按住动作在结束或异常时释放。验收：长动作各阶段插入 STOP，不再输出旧动作。
- [ ] T02-05 校准与独立检查点。验收：测试 Activity 收到实际鼠标事件，误差达标才启用坐标动作；旋转或校准失效禁止旧坐标。
- [ ] T02-06 真机手控验证。验收：OTG、供电、USB 枚举、点击/拖动/ASCII、蓝牙断连、USB 拔插和释放的实物报告。当前无安卓真机，此项必须保留待完成。

### M3：手机端 Agent

- [ ] T03-01 任务状态机与单动作执行。验收：每条动作绑定观察与任务代际；未知动作/越界参数无设备输出。
- [ ] T03-02 规划、动作后核验及独立完成检查。验收：假模型谎报 done、无画面变化、页面遮挡均不会被直接标记成功。
- [ ] T03-03 暂停、停止、人工接管和恢复。验收：停止后模型迟到响应及旧设备回调不复活任务；恢复重新观察，不续跑旧队列。
- [ ] T03-04 动作数、任务时间、模型调用次数和失败预算。初值建议 40 次输入、10 分钟、最多 90 次模型调用、连续失败 3 次；它们是 App 限制，不是网关余额或账单保证。验收：触顶立即停止/暂停并释放。
- [ ] T03-05 通用任务验收：测试画布点击/拖动、ASCII 编辑框填写、设置页只读导航。验收：明确初始页面、目标和结果，记录步骤、失败及恢复；模拟与真实模型结果分开。

### M4：中文与聊天辅助

- [ ] T04-01 InputMethodService 和人工启用/选择引导。验收：没有无障碍服务；未选中本 IME 时不提交中文；普通点击任务可不启用 IME。
- [ ] T04-02 编辑会话、焦点及同 UID/签名保护 IPC。验收：编辑会话变化使待提交作废，外部未授权广播/组件不能注入文字。
- [ ] T04-03 `commitText` 和草稿核验。验收：中文、标点、emoji、换行、长文本；物理键盘导致软键盘隐藏仍正确管理 InputConnection；不可核验时进入待确认，不宣称成功。
- [ ] T04-04 当前一对一聊天的视觉解析。验收：包名不能代替联系人识别，重名/群聊/弹窗/遮挡/页面切换进入不确定并暂停。
- [ ] T04-05 消息实例和候选流程。验收：同内容连续两条视为不同实例；滚动重现不盲目重复回复；用户返回 App 选候选期间暂停硬件输入，回到目标后重新观察再填入。
- [ ] T04-06 中文回复闭环。验收：候选经确认后写入正确草稿；首版由用户手动发送，输入成功不显示“消息已发送”。

### M5：试用交付

- [ ] T05-01 APK 与固件版本关联、签名和发布清单。验收：不兼容版本拒绝控制，有明确升级与恢复说明。
- [ ] T05-02 无品牌白名单的能力自检。验收：按 BLE、USB、投影与 IME 状态提示问题；不以手机品牌直接禁用，也不把未验证机型标为已通过。
- [ ] T05-03 安装、权限、蓝牙绑定、校准、Key、输入法与停止教程。验收：运行流程无需电脑与 ADB；开机不自动开始录屏或任务。
- [ ] T05-04 隐私、日志清理、故障导出和崩溃恢复。验收：敏感数据不进入默认记录；恢复不重放旧操作。
- [ ] T05-05 实物验收与发布记录。验收：报告实际系统/硬件/输入法/目标 App 组合、重复次数与失败，不只展示一次成功录像；无真机时只交付开发构建和模拟报告，不标为硬件正式通过。

### M6：受限自动发送（后续独立阶段）

- [ ] T06-01 明确启用开关、会话范围、文本规则与人工恢复路径。验收：用户消息不能扩大联系人或动作权限。
- [ ] T06-02 发送前验证联系人、草稿与页面；发送后验证消息实例。验收：点击结果不确定进入 `SEND_UNKNOWN`，不自动二次点击或重发。
- [ ] T06-03 长时间前台聊天监测、断线、权限撤销和调用预算。验收：不把投影停止或微信不在可见范围解释为仍能监测后台消息。

## 4. 可先开展与必须等真机的工作

| 可先在 Windows/模拟器完成 | 不能用模拟替代 |
|---|---|
| APK 构建、界面、Key 存储、模型假接口与解析 | 实物手机 OTG 和 ESP32 复合 HID 枚举 |
| MediaProjection 授权/旋转/停止的系统镜像测试 | 厂商省电、真实后台服务、蓝牙重连行为 |
| IME 向调试编辑器提交中文 | 物理键盘接入后 IME、焦点与实际微信配合 |
| BLE 编码、密码测试向量、MTU/丢包模拟 | 射频环境、真实 MTU、停止时延和耗电 |
| 固件编译、动作引擎假 HID sink、异常注入 | 校准精度、输入释放是否实际被手机接收 |
| Agent 假截图/假模型状态机 | 模型在真实手机页面上的完成质量 |

## 5. 核心验收矩阵

下面是设计目标，不是已通过结果。

| 编号 | 场景/注入 | 预期与证据 | 验证层 |
|---|---|---|---|
| A01 | APK manifest 与功能路径 | 没有 AccessibilityService/BIND_ACCESSIBILITY_SERVICE；无 ADB/Root 执行路径 | 构建审计 |
| A02 | 录屏拒绝、撤销、锁屏、旧令牌复用 | 禁止继续输入，释放资源；重新授权才恢复 | 系统镜像＋真机 |
| A03 | 单应用共享却要操作其他应用 | 观察范围不足时拒绝继续；不声称 HID 被系统锁在单应用 | 系统镜像＋真机 |
| A04 | 无新帧、旧帧、旋转、尺寸变化 | 作废旧观察；无可验证新观察不执行 | 单元＋镜像＋真机 |
| A05 | 错误凭证、篡改、重放、第二客户端 | HID sink 记录为零，合法控制者状态不被越权更改 | 协议模拟＋实物 |
| A06 | MTU=23、分片中断、心跳/停止插入 | 不越界、不无限等待；控制包不排在完整长包之后 | 模拟＋实物 |
| A07 | STOP 与下一 HID 报告并发 | 撤销后旧动作不再输出，确认释放才回 stopped | 时序模拟＋实物 |
| A08 | 模型在停止/暂停后返回 | 不再提交任何设备动作 | 单元＋集成 |
| A09 | 同命令重复、结果丢失、重启 | 同会话不重复执行；跨会话标未知，先观察，不自动重放 | 协议＋集成 |
| A10 | BLE/USB 断开或释放失败 | 本地清理，未实际发送释放时如实标记；恢复先中性报告 | 模拟＋实物 |
| A11 | 非法 JSON、动作越界、拒答/截断 | 无输入，保留分类错误，不执行半条响应 | 单元＋假服务器 |
| A12 | 校准不准/速度设置变化 | 检查点失败则不放行坐标输入；引导重新校准 | 真机 |
| A13 | IME 未选、失焦、编辑连接切换、外部注入 | 不提交中文；旧编辑会话的任务失效 | 镜像＋真机 |
| A14 | USB 键盘接入、软键盘隐藏、读回不可用 | 不靠面板可见判断连接；不能确认草稿则待确认 | 真机 |
| A15 | 相同内容两条、滚动重现、重名联系人 | 保留消息实例，不凭单文本哈希或昵称自动发送 | fixtures＋真机 |
| A16 | Key/secret 出现在异常、日志或备份 | 默认导出无明文凭证；修改端点后不把旧 Key 静默发给新域名 | 单元＋构建审计 |
| A17 | 超步数/时间/调用数/失败上限 | 明确原因，撤销任务并释放输入；不继续隐式调用 | 集成 |
| A18 | 微信发送回执不确定 | `SEND_UNKNOWN` 暂停，无重复触发发送 | M6 集成＋真机 |

STOP 与重放类模拟测试使用可复现随机种子、多阶段注入，首轮至少 100 个时序组合；真实硬件次数与耗时分布单独记录。时延拟定目标为健康 BLE 下停止输出 300 ms、心跳失联 1.5 秒；测量方式和不达标原因写报告，不能将拟定目标写成已完成指标。

## 6. 交付清单与报告格式

每一阶段交付可定位源码、实际构建命令、软件测试报告、未完成项；具备真机时追加实物报告。最终交付签名 APK、受支持 S3 固件、版本/依赖和许可清单、协议文档、用户安装教程、原固件恢复说明。

测试报告至少包含：代码 commit、APK/固件 hash、Android/API、手机与板子、输入法/目标 App 版本、网络与模型、起始页面、操作次数、成功/失败/不确定、停止时延和原始证据位置。没有某项测量就写未测，界面上的本地 token 估算不得冒充网关计费。

后续估时以工作包完成情况、真实构建与设备结果更新。当前没有真机，可以完成设计、代码、构建与模拟，但不承诺某个日期“全部安卓手机可用”。
